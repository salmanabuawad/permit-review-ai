# AI Gateway: architecture

## Today (PARTIAL)

`backend/app/ai/gateway.py` and `relay.py` provide:

- **Providers:** the local model through the relay to the user's PC (llama.cpp, one GPU model at a time), local BM25,
  and a template fallback. There is no cloud provider and none is configured.
- **Policy:** a per-tenant AI policy (`ai_policies`, AI settings page); local-only by default.
- **Recording:** tokens in and out, latency and cost per call (`inference_costs`, run metrics).
- **Use:** document typing, the run summary with cited KB passages, and drawing reading (vision, on the AI PC).

## Target components

| Component | Purpose | State |
|---|---|---|
| Provider abstraction | local (llama.cpp / Ollama / vLLM), cloud (only with explicit authorisation), all behind one interface | P |
| Model registry | id, repository, pinned revision, licence, checksum, quantisation, context, VRAM, tasks it is validated for | — |
| Task router (`LocalAIModelRouter`) | task → validated model; escalation on objective triggers | — |
| Prompt registry | prompt id + version, frozen text, output JSON schema | — (prompts inline in code) |
| Structured output validation | JSON schema; reject and escalate on failure | P (typing validates labels) |
| Response cache | key = (task, prompt version, model, quantisation, evidence fingerprints, tenant) | — (summary is not cached; about 94 % of run time) |
| Token budget | evidence selection, de-duplication, task limits | P (passages capped) |
| Cost and usage tracking | per application, stage, model | I |
| Audit | every call: model, prompt version, input fingerprint, outcome | P |
| GPU scheduler | one queue on the AI PC, model residency, timeouts, OOM recovery | P (router `--models-max 1`, idle unload) |

## Routing policy

| Task | Default executor |
|---|---|
| text extraction, numbers, geometry, comparisons | deterministic code: **no LLM** |
| document classification | rules first, then a small local model |
| embeddings | multilingual-e5-small on the server CPU (approved 2026-11-26; benchmark pending) |
| regulatory clause extraction | local LLM with schema validation |
| ambiguous interpretation, exceptions, relief justification | stronger local model, escalated only on objective triggers |
| report text | deterministic templates; the LLM only for the optional narrative summary |

Escalation triggers are objective: missing evidence, schema failure, numeric disagreement with the source, a possible
exception, or inconsistent applicable rules. They are never the model's self-reported confidence. If a stronger model
cannot settle the question from the evidence, the check is UNRESOLVED.

## Data protection

- Uploaded and crawled content is untrusted data. It goes inside delimited evidence blocks, instructions in it are
  ignored, and outputs are validated against a schema.
- Restricted municipal documents never go to a cloud provider without explicit authorisation per tenant and task, and
  the system never silently falls back to the cloud. That is the current behaviour, kept.
- Model files come from approved repositories with pinned revisions and checksums. `trust_remote_code` is off unless
  the code has been reviewed.
