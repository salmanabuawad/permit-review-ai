# 08 — ניהול כללים דרך API ובדיקה חוזרת

מסך: **מאגר כללים** (`/rules`) · API: `/api/rules/*` · קוד: `backend/app/rules_api.py`

> הערה: תת-מערכת **סריקת המקורות** (crawler) הוסרה. מקורות רשמיים נרשמים ב־`knowledge/sources.yaml` ומאומתים ידנית; כללים מנוהלים דרך ה־API שלהלן. היסטוריית ההחלטה: `reports/105_reconciliation_report.md`.

## מה ה־API עושה
כללים ב־`knowledge/rules/*.yaml` הם קו הבסיס. כלל שנכתב דרך ה־API נשמר לכל רשות ב־`managed_rules` ו**דורס** את כלל הקובץ בעל אותו מזהה; מחיקה **מסתירה** כלל (מקובץ או מ־API) בלי לאבד אותו. כל שינוי נשמר ב־`rule_revisions` וביומן הביקורת.

| פעולה | בקשה | הערות |
|---|---|---|
| קריאה | `GET /api/rules/{id}?format=json\|yaml` | כלל אחד; `format=yaml` מחזיר גוף שניתן לערוך ולהחזיר ב־PUT |
| ייצוא | `GET /api/rules/export` | כל הכללים בתוקף לרשות, כקובץ YAML יחיד (אותה צורה כמו `knowledge/rules/*.yaml`) |
| היסטוריה | `GET /api/rules/{id}/history` | כל גרסה: פעולה, מבצע, זמן, נימוק, גוף מלא |
| יצירה | `POST /api/rules` | כלל אחד, או `{rules: [...]}` במכה אחת (הכול-או-כלום) |
| החלפה | `PUT /api/rules/{id}` | גוף מלא; מזהה חייב להתאים ל־URL |
| עדכון חלקי | `PATCH /api/rules/{id}` | רק שדות שנשלחו; `null` מוחק שדה אופציונלי |
| מחיקה | `DELETE /api/rules/{id}` | מסתיר את הכלל מבדיקות עתידיות; הרצות עבר שומרות ממצאים |

גוף הבקשה הוא JSON או YAML (לפי `Content-Type`, או זיהוי אוטומטי ל־`curl -d`). עד 1MB.

## בטיחות
- **ה־API לעולם אינו מסמן כלל כ"מאושר מקצועית".** אישור ניתן רק ב־`POST /api/rules/{id}/approval` (מהנדס העיר / מנהל אגף).
- **כל שינוי יוצר גרסה חדשה**, ולכן אישור קודם אינו חל עליה — נדרש אישור מחדש כדי שהכלל יהיה מחייב.
- כלל נבדק מול מנוע הכללים בעת הכתיבה (הרצת בדיקה על עובדות ריקות); כלל שבור מבנית נדחה מיד (422).
- `source_id` חייב להופיע ברשם המקורות (`knowledge/sources.yaml`), אחרת הבקשה נדחית.
- הרשאה: `rule.manage` (מנהל מערכת, מהנדס העיר, מנהל אגף) לכתיבה; `case.read` לקריאה. כל פעולה נרשמת ביומן הביקורת.

## טבלאות (מיגרציה `0004`)
`managed_rules` (הכלל הפעיל לכל רשות, `status = active | deleted`) · `rule_revisions` (כל יצירה / עדכון / מחיקה / שחזור עם הגוף המלא — לעולם לא נערך).

## בדיקה חוזרת
- **רשימת התיקים:** "בדיקה חוזרת" מריץ מחדש את בדיקת הכללים על התיקים שנבחרו, או על כל התיקים אם לא נבחר אף אחד (עד 500). תיק נעול או ללא מסמכים — מדולג עם סיבה; כשל בתיק אחד אינו עוצר את השאר. API: `POST /api/cases/recheck`.
- **מסך התיק:** הכפתור "הרצת בדיקה" נקרא "בדיקה חוזרת" כשכבר קיימת הרצה.
- שימוש טיפוסי: אחרי אישור או שינוי כלל — להריץ בדיקה חוזרת כדי שהתיקים יחושבו לפי מאגר הכללים העדכני (כל הרצה נשמרת כגרסה חדשה).

## מקורות שאי אפשר לשלוף אוטומטית
gov.il מחזיר 403 לבקשות אוטומטיות; mavat היא אפליקציית JavaScript ללא קישורים ישירים למסמכים (ראו רשם המקורות, סעיף ה׳). לכן מסמכים רשמיים מועלים ונרשמים ידנית, ומאומתים לפני שהם הופכים לכללים.
