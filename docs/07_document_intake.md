# 07 — קליטת מסמכים (Document Intake)

מסך: **תיקי בקשות ← קליטת מסמכים** · API: `/api/import/*` · קוד: `backend/app/intake/`

## צנרת העיבוד
מסמך → חילוץ טקסט (ישיר מה־PDF; OCR רק לעמודים ללא שכבת טקסט) → **סיווג לפי תוכן** → זיהוי בקשות (כולל פיצול פרוטוקול לפריטים) → **חילוץ מובנה** (ספק AI ניתן להחלפה) → **אימות**: סכמת Pydantic + בדיקת עיגון (ערך שאינו מופיע בטקסט — מושמט) + הצלבה מול קובץ האינדקס → תצוגה מקדימה לעריכה → אישור → מסד הנתונים.

| שלב | מודול | הערות |
|---|---|---|
| פריסת ZIP | `batch_import.unpack` | הגנה מ־path traversal, zip bomb, 500 קבצים; ZIP מקונן — דולג עם אזהרה |
| טקסט + OCR | `intake/pipeline.py` | PyMuPDF; עמודים ללא טקסט → משימת `OCR` בשער ה־AI; אם אין ספק פעיל — "נדרש OCR" |
| סיווג | `intake/classify.py` | לפי סימנים בתוכן (כותרות פרוטוקול, החלטה, סימוני BAKPIRUT/TBPIRUT, הוראות תכנית, שדות טופס, צפיפות שרטוט) — לא לפי שם הקובץ |
| פרוטוקול ועדה | `intake/protocol.py` | פיצול לפריטי בקשה (BAKPIRUT) ולפריטים תכנוניים (TBPIRUT — לא הופכים לבקשה); תוויות מזוהות לפי אותיות, עמיד לשיבושי כיווניות |
| טופס בקשה | `batch_import.extract_fields` | "תווית: ערך" בשני כיווני השורה; PDF עם כמה טפסים — מפוצל |
| אינדקס | `intake/metadata.py` | `index.csv/json/html` ורשימות Excel — **לעולם לא יוצרים בקשה**; משמשים להתאמה (קובץ/תיקייה/מספר), השלמת חסרים, הצלבה ועמודים במקור |
| עיגון | `intake/grounding.py` | כל ערך של כל ספק נבדק מול טקסט המסמך |
| שמירה | `intake/commit.py` | אידמפוטנטי: בקשה קיימת → "כפולה" או "עודכנה" (רק מסמכים חדשים לפי SHA-256); כל בקשה ב־savepoint — כשל לא עוצר את השאר |

## סוגי מסמכים
טופס בקשה להיתר · פרוטוקול ועדה · מסמך תכנוני (תכנית/תקנון) · תכנית אדריכלית (DXF/DWG או PDF שרטוט) · מסמך נלווה · קובץ אינדקס.

## שדות שמחולצים (כשמופיעים במסמך — לא מומצאים)
מספר בקשה · תיק בניין · כתובת · גוש וחלקה · יעוד · שטח מגרש · סוג בקשה (כנוסחו + סיווג מערכת) · מהות הבקשה · תוכניות חלות (נוסח גולמי) · הקלות · שטחים קיים/מוצע לפי קומה · הערות לפי גורם (מחלקת רישוי, אדריכל חזות העיר, מהנדס העיר, אדריכל רישוי, מח' תב"ע, יועמ"ש…) · החלטת הוועדה (תוצאה, נוסח, תנאים, ישיבה ותאריך) · הליך (חידוש, דיון חוזר, ועדת ערר, שינויים להיתר).
לכל ערך: קובץ, עמוד בקובץ, עמוד בפרוטוקול המקורי (מהאינדקס), ציטוט, שיטה, ודאות, ספק. **אין חילוץ של שם מבקש/עורך/ת.ז.**

## מודל הנתונים (הרחבה — מיגרציה `0002`)
| ישות | טבלה |
|---|---|
| בקשות | `permit_cases` (+ `building_file_number`, `application_type`, `source`, `import_batch_id`, ייחודיות `tenant_id+case_number`) |
| מסמכים | `case_files` (+ `doc_class`, `origin` — עמודים מתוך מסמך גדול) |
| סיווגי מסמכים | `document_classifications` |
| שדות מחולצים | `extracted_fields` (ערך, ערך מקורי אם נערך, ודאות, מצב auto/edited) |
| הפניות מקור | `source_references` |
| הערות תכנוניות | `planning_comments` |
| החלטות ועדה | `committee_decisions` |
| עבודות עיבוד | `processing_jobs` |
| אצוות ייבוא | `import_batches` (הקבצים המקוריים נשמרים עם האצווה) |
| הרצות AI | `inference_costs` (+ `job_id`, `input_sha256`) |

מיגרציות: Alembic (`backend/migrations`). `0001` = הסכמה הקיימת; `0002` = הישויות החדשות. מסד שנוצר לפני המיגרציות מסומן ב־0001 ואז משודרג — הנתונים נשמרים (נבדק). המיגרציות רצות אוטומטית בעליית השרת, ונבדקו על SQLite ועל PostgreSQL 16.

## הרצת בדיקות
```bash
cd backend && ../.venv/Scripts/python -m pytest -q
```
בדיקות הקבלה על החבילה האמיתית (`tests/test_acceptance_package31.py`) קוראות את הקבצים מ־`BBP_TEST_PACKAGE_31` / `BBP_TEST_PROTOCOL` (ברירת מחדל: תיקיית ההורדות) ומדולגות אם אינם קיימים — החבילה כוללת שמות אנשים ואינה נשמרת במאגר.
על PostgreSQL: `BBP_TEST_DATABASE_URL=postgresql+psycopg://…` (למשל מופע `pgserver` מקומי).
דוח תוצאות: `python scripts/import_report.py --with-tests` → `docs/reports/import_test_report.md`.

## בעיות פתוחות
1. **תוכניות חלות** — הנוסח בייצוא מהמערכת משובש בכיווניות (למשל `105 / 'ב105, / /ד2`); נשמר כנוסח גולמי בוודאות 50% ומסומן "נדרש אימות". אין פענוח למספרי תכנית תקניים.
2. **טבלת שטחים** — פענוח מבני מיטבי (ודאות 60%); בבקשות גדולות (תמ"א 38) נוצרות עשרות שורות שחלקן שגויות בתווית הקומה. דורש אימות בודק.
3. **סיווג סוג הבקשה** — לפי מילות מפתח במהות הבקשה (ודאות 70%); בבקשה עם כמה רכיבים נבחר הרכיב הדומיננטי לפי סדר עדיפות (בנייה חדשה › איחוד חלקות › שינויים להיתר › חדרי גג › סוכה › מרפסת › תוספת).
4. **תוצאת החלטה** — "לבטל החלטה" וניסוחים חריגים מסווגים "אחר — נדרש עיון" (1 מתוך 31).
5. **שיבושי ניקוד בטקסט** — נקודות בתוך מילים ("לס.מן") ומילים מפוצלות נשמרות כפי שהן במקור (הציטוט נאמן למסמך).
6. **OCR** — אין ספק OCR פעיל (Tesseract לא מותקן); עמודים סרוקים מסומנים "נדרש OCR" ולא מחולצים.
7. **ספק LLM מקומי** — מימוש קיים ונבדק עם ספק מדומה בלבד; לא הורץ מול מודל אמיתי ולא נמדד דיוקו.
8. **אימות מול טופס בקשה מקורי** — החבילה כוללת פרוטוקולים בלבד; חילוץ מטופסי רישוי זמין אמיתיים לא נבדק.
9. **שרת החי** — רץ על SQLite; המעבר ל־PostgreSQL בשרת דורש החלטה והגדרה (המיגרציות מוכנות ונבדקו).
